# AI Architecture

## Load When

Use for enemy AI, squad AI, StateTree, Behavior Tree, perception, navigation, targeting, or high unit counts.

## Choose AI Complexity by Unit Role

### StateTree / Behavior Tree
Good for:
- bosses
- elites
- squad leaders
- companion characters
- complex authored behavior

### Lightweight State/FSM
Good for:
- large numbers of simple enemies
- deterministic combatants
- simple tower-defense agents

### Central Scheduling / Batched Logic
Consider for high counts to reduce per-Actor overhead.

## Navigation

Choose by problem:

- Recast NavMesh for conventional character navigation
- custom grid/A* for strategic placement/path validation
- flow fields for large groups moving toward shared goals
- local steering/formation logic for squad cohesion

Hybrid games may use more than one navigation layer.

## Targeting

For large counts, avoid naive all-to-all scans.

Consider:

- spatial partitioning
- cached candidate sets
- batched queries
- range buckets

## Tick

Do not give every AI actor expensive Tick work by default.

Use:
- timers
- centralized schedulers
- event-driven transitions
- significance-based updates

## Rule

AI architecture should match expected population, not only behavior complexity.
