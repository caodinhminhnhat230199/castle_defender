# Quality Gates

## Load When

Use before moving between major phases or declaring work done.

## Specification Gate

- player behavior is clear
- scope is bounded
- important rules have IDs
- open questions are visible
- anti-goals exist for large systems

## Technical Plan Gate

- all approved requirements have an approach
- existing architecture was considered
- project-specific claims are verified
- risks are explicit
- performance-sensitive areas are identified

## Task Gate

- tasks are small and testable
- dependencies are clear
- acceptance criteria exist
- testing work exists

## Prototype Gate

- hypothesis answered
- result is keep/change/delete
- prototype debt is identified

## Vertical Slice Gate

- representative loop works end-to-end
- production pipeline is viable
- core performance direction is acceptable

## Implementation Gate

- build succeeds
- runtime behavior works
- relevant tests pass
- no unsupported design change occurred

## Release Gate

- packaged build tested
- blocking regressions resolved
- known issues recorded
- required documentation updated

## Definition of Done

A game feature is done only when it is:

**implemented + integrated + verified + playable**.
