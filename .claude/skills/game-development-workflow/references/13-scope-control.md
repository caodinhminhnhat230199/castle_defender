# Scope Control

## Load When

Use whenever new ideas appear during implementation or planning.

## Classification

Every new idea becomes one of:

```text
REQUIRED
IMPROVEMENT
FUTURE
OUT OF SCOPE
```

Do not silently add `IMPROVEMENT` or `FUTURE` work to the current feature.

## Anti-Goals

Large systems should include explicit anti-goals.

Examples:

- not a full RTS
- no individual unit micromanagement
- no deep crafting chain
- no city simulation
- no fully procedural world

Anti-goals are decision tools.

## Scope Change Check

Before accepting new work, ask:

1. Does it unblock the current gameplay loop?
2. Does it satisfy an approved requirement?
3. Does it reduce a major technical risk?
4. What schedule/content cost does it add?
5. What existing work does it invalidate?

## Rule

A good idea is not automatically a current-scope idea.
